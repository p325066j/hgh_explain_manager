# HGH Explain Manager UI ガイドライン

最終更新: 2026-02-19

## 1. デザインのゴール / トーン

- **目的**: 医療スタッフが安心して動画を管理し、患者が迷わず動画を視聴できる UI を提供する。
- **トーン**:
  - 安心感・信頼感（医療らしい落ち着いたトーン）
  - 情報量は多くても「整理されていて見つけやすい」
  - 患者向け画面はシンプル・直感的、スタッフ向け画面は効率重視

---

## 2. カラーパレット

Tailwind のカラートークンと合わせて **ブルー系をキーカラー** とする。

### 2.1 ベースカラー

- **背景（ダークテーマ前提）**
  - ページ背景: `#dfdfdf`（`slate-950` 近似）
  - セクション / カード背景: `#020617`〜`#0f172a`（`slate-900`〜`slate-950`）
- **テキスト**
  - メイン: `#191919`（`slate-200`）
  - サブ: `#249191`（`slate-400`）
  - 無効・補足: `#f16124`（`slate-500`）

### 2.2 アクセントカラー

- **プライマリ（行動色）**
  - ベース: `#249191`（`sky-500`）
  - ホバー: `#1a6a6a`（`sky-400`）
  - バックグラウンド: `#2491911a` 〜 `#2491910d`
- - **セカンダリ（補助アクション）**
  - ベース: `#191919`（メインテキストと同系の濃いグレー）
  - ホバー: `#333333`
  - バックグラウンド: `#0000000a`〜`#00000014`
- **ステータス**
  - 成功: `#22c55e`（`green-500`）
  - 注意: `#f59e0b`（`yellow-500`）
  - エラー: `#f97373`〜`#ef4444`（`rose-400`〜`rose-500`）


### 2.3 使用ルール

- **プライマリボタン**  
  - 背景: `#249191`（または `bg-[#249191]`）
  - ホバー: `#1a6a6a`
  - テキスト: 常に白（`#ffffff`）
- **セカンダリボタン**  
  - 背景: ページ背景と同系（`#dfdfdf` またはカード内なら `#020617`）
  - 枠線: `#191919` または `#249191`
  - ホバー: 背景をわずかに濃くし、テキストカラーを `#191919` に寄せる
- **アウトラインボタン**  
  - 通常: 枠線 `#249191`、テキスト `#249191`、背景は透明
  - ホバー: 背景を `#24919114` 程度で薄く色付け
- **エラー表示**  
  - 枠線: `#f97373`〜`#ef4444`
  - 背景: `#fee2e2`（ライトテーマ時）または `#f973731a`（カード内がダークテーマの場合）
  - テキスト: `#b91c1c`
- **リンク**  
  - 通常: `#249191`
  - ホバー: `#1a6a6a`、下線を表示

## 3. タイポグラフィ

- **ベースフォント**: システム UI フォント（`system-ui`, `-apple-system`, `"Segoe UI"`, `"Noto Sans JP"` など）
- **サイズの目安**
  - ページタイトル: `text-2xl`〜`text-3xl`
  - セクション見出し: `text-lg`〜`text-xl`
  - 本文: `text-sm`〜`text-base`
  - 補足・ヘルプテキスト: `text-xs`
- **太さ**
  - 見出し: `font-semibold`
  - 本文: `font-normal`
  - ボタン: `font-semibold`

---

## 4. レイアウト / コンポーネント方針

### 4.1 レイアウト

- 最大幅: PC ではコンテンツ幅 `max-w-5xl`〜`max-w-6xl` を中心に配置。
- 余白:
  - ページ左右余白: `px-4`〜`px-8`
  - セクション上下余白: `py-8`〜`py-12`
- グリッド:
  - スタッフ向け: 2 カラム（一覧 + 詳細）を基本としつつ、フォームは 1 カラムで縦に並べる。
  - 患者向け: 1 カラムのカードリストを基本。スマホ前提で横スクロールは避ける。


### 4.2 ボタン

- **プライマリボタン**
  - 用途: 「登録する」「保存する」「一括反映」のようなポジティブな主要アクション。
  - 例: `bg-[#249191] text-white hover:bg-[#1a6a6a] disabled:opacity-60`
- **セカンダリボタン**
  - 用途: 「戻る」「キャンセル」「絞り込み解除」など。
  - 例（ライト背景上）: `border border-[#191919] text-[#191919] hover:bg-black/5`
  - 例（ダークカード内）: `border border-white/30 text-slate-100 hover:bg-white/10`
- **破壊的アクション**
  - 用途: 削除など。
  - 例: `border border-rose-500 text-rose-600 hover:bg-rose-500/10`

## 5. フォーム / バリデーション

- 入力欄は原則として **フル幅のテキストフィールド**。
- プレースホルダには「入力例」を書く（抽象的な説明だけにしない）。
- **エラー表示**
  - フィールド直下に `text-xs text-rose-200` で 1 行表示。
  - フォーム全体のエラーは上部のアラートボックス（背景 `rose-500/10`、枠 `rose-400/40`）で表示。
- 必須項目にはラベルに「*」を付けない代わりに、項目説明やプレースホルダで明示する。

## 6. スタッフ向け画面と患者向け画面の違い

### 6.1 スタッフ向け（/staff）

### 6.1 スタッフ向け（/staff）

- 情報密度: 中〜高。テーブル・フィルタ・バッジなどで状態を一覧できるようにする。
- 色: ベースはライトグレー背景（`#dfdfdf`）とダークカード（`#020617`）の組み合わせ。強調にはプライマリカラー `#249191` を用い、エラー・注意はステータスカラーを使う。
- ナビゲーション: 左または上部に常時表示のメニュー（ダッシュボード / 動画 / カテゴリ / 設定 等）。

### 6.2 患者向け（/patient）

- 情報密度: 低〜中。タイトル・サムネイル・カテゴリ・簡単な説明に絞る。
- 色: プライマリカラーはそのまま使いつつ、余計なボタンを出さず「視聴に集中できる」ことを優先。
- 操作: 1 画面 1 アクション（動画一覧 → 動画詳細）の流れをシンプルに保つ。

## 7. レスポンシブ / デバイス対応

- **ブレークポイント**
  - モバイル: ～ `640px`
  - タブレット: `640px`～`1024px`
  - デスクトップ: `1024px` 以上
- 患者向け画面は **モバイルファースト**（スマホの縦画面で最適化）。
- ボタンやタップ対象の最小サイズは `min-h-[44px]` 程度を目安にする。

---

## 8. アクセシビリティ

- コントラスト比: 主要テキストと背景のコントラストは **WCAG AA** 相当以上を目標。
- フォーカス可視化: キーボード操作時には、ボタンやリンクに **明確なアウトライン** を表示する（`outline` / `ring` など）。
- ラベル:
  - すべてのフォーム要素に `<label>` を対応させる。
  - アイコンボタンには `aria-label` を設定。

---

## 9. コンポーネント再利用の方針

- よく使う UI パターン（カード、セクションのラッパー、プライマリボタン、フォームフィールド）は `components/ui` などに分離し、**スタイルの一貫性を保つ**。
- 新しい画面を作る際は、まず既存のコンポーネントを再利用・拡張できないか検討する。
